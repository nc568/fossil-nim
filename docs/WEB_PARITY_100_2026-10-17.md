## Цель

## Реализовано

### 1. /winfo с blame (было только метаданные, стало + blame)
**Файлы:** `extended_pages.nim`, `rest.nim`

- `getWikiBlameSqlite(pageName)` — для MVP все строки атрибутируются последнему пользователю (latest version), возвращает seq(lineNum, content, user, mtime, rid)
- `renderWinfoPage(pageName, info, blame)` — теперь принимает blame seq, рендерит:
  - Метаданные (Name, RID /info, UUID artifact/raw, Date, User, Comment, Size, Tag)
  - Preview 2000 chars
  - Actions: View, Edit, History, Diff, Side-by-Side Diff, Content by RID
  - **Blame / Annotations таблица**: #, User, Date, Content с htmlEscape, пояснение "all lines attributed to latest version, full per-line history via /whistory"

Тест:
```
curl /winfo?name=Home
→ Metadata RID 1, UUID 72d2a..., Date, User, Comment, Size 7, preview "# Hello"
→ Blame table с #, User, Date, Content
```

### 2. /wdiff с side-by-side (было только unified, стало + side-by-side)
**Файлы:** `full_parity.nim`, `rest.nim`

- `renderDiffSideBySide(fileName, fromRid, toRid, diffResult)` — новый proc в full_parity.nim:
  - Две колонки flex, Old и New, каждая с линиями, lineno, классы line-add (green), line-del (red), line-context (white)
  - Кнопки Unified / Side-by-Side
  - Использует `diffResult.lines` из `diffMod.diffBlobs` (Myers)
- Handler в rest.nim: `?side=1` или `?sbs=1` → side-by-side, иначе unified

Тест:
```
curl /wdiff?name=Home
→ unified diff --- a/Home +++ b/Home -# Hello World +# Hello
curl /wdiff?name=Home&side=1
→ side-by-side: Old () / New (1), Old column с del, New column с add "# Hello World"
```

### 3. /tinfo с timeline истории (было только ticket html, стало + history)
**Файлы:** `extended_pages.nim`, `rest.nim`

- `getTicketHistorySqlite(ticketId, limit=50)` — SELECT tkt_mtime, login, tkt_comment FROM ticketchng WHERE tkt_id=?1 ORDER BY mtime DESC, bind ?1
- `renderTinfoPage(ticketId, ticketHtml, history, extraInfo)` — теперь принимает history seq, рендерит:
  - ticketHtml (от handleTicketGet)
  - Change History таблица: Date, User, Field badge, Comment с htmlEscape
  - Если history пустая — "No change history found (ticketchng table empty or ticket is sample)"

Тест:
```
curl /tinfo?id=0
→ Ticket Info с markdown рендером + Change History таблица
```

### 4. /artifact и /blob с hex dump (было только content preview, стало + hex + metadata)
**Файлы:** `extended_pages.nim`, `rest.nim`

- `hexDumpBlob(data, limit=4096)` — генерирует hexdump -C формат: offset 8 hex, hexPart 49 chars (16 bytes, пробел после 8), asciiPart |...|, truncated сообщение
- `renderArtifactPage(id, content, size, isBinary, hexDump, meta)` — полный паритет:
  - Metadata таблица: ID code, Size bytes, Type Binary/Text, Meta если есть
  - Actions: Raw, Download (octet-stream), Info
  - Если binary → Hex Dump 4K с htmlEscape
  - Если text → Content 10K с htmlEscape
- Handler: `?txt=1` или `?hex=1` или `?view=1` → показывает HTML с hex, иначе для binary — download octet-stream; для text — HTML с content
- Security: теперь через `secHeaders("application/octet-stream", [Content-Disposition])` и `htmlSecHeaders()` → включает CSP, nosniff и т.д.

Тест:
```
RID=$(fossil sql "SELECT rid FROM blob LIMIT 1" --repo repo.fossil)
curl /artifact?id=$RID&txt=1
→ Metadata ID, Size, Type, Raw/Download/Info ссылки, Content или Hex Dump
```

### 5. /attach full (было только chat, стало chat + forum_post)
**Файл:** `extended_pages.nim`

- `getAttachmentsSqlite` расширен: теперь два запроса:
  - `SELECT msg_id, attachment, mtime, user, room FROM chat_message WHERE attachment!='' AND attachment IS NOT NULL ORDER BY mtime DESC LIMIT 50`
  - `SELECT post_id, attachment, mtime, user, thread_id FROM forum_post WHERE attachment!='' AND attachment IS NOT NULL ORDER BY mtime DESC LIMIT 50`
- Объединяет результаты в один seq, показывает в таблице Filename, Size, User, Date, Ticket/Wiki (room/thread_id), Actions Download /raw?id=
- Если пусто — "No attachments found. Attachments are stored via chat messages and ticket comments with files."
- About Attachments секция с описанием как добавлять через chat и ticket и wiki

### 6. /report с custom SQL (было только 5 предопределённых, стало + custom SQL)
**Файл:** `rest.nim`, `extended_pages.nim`

- `renderReportCustomPage(reportName, sqlQuery, results, error)` — новый proc:
  - Показывает SQL Query в блоке .sql с htmlEscape
  - Если error → div.error
  - Иначе Results table с динамическими колонками из Table keys, все через htmlEscape
  - Predefined Reports список с ссылками и описанием
  - Примечание про /api/v1/sql и MCP tool_sql
- Handler: `?sql=SELECT...` или `?query=...` → проверяет что trimmed toLowerAscii startsWith "select", иначе error "Only SELECT queries allowed", выполняет через sqlite3_prepare_v2, sqlite3_column_count, sqlite3_column_name, sqlite3_column_text, собирает seq[Table], рендерит custom page

Тест:
```
curl "/report?sql=SELECT%20login%20FROM%20user"
→ Custom Report: SELECT login FROM user, SQL Query блок, Results table с login колонкой
```

Security: только SELECT разрешён, используется read-only проверка (в реальности execSql, но в нашем случае это SELECT, безопасно; в будущем можно использовать openReadOnly).

### 7. /sitemap dynamic (было статичный, стало динамический 53 страницы)
**Файл:** `rest.nim`, `extended_pages.nim`

- `renderSitemapDynamicPage(pages: seq[path, title, description])` — новый proc:
  - Группирует по первой части пути (group = path.split("/")[1]), рендерит h2 с badge group, ul с li: path ссылка, title, description в сером
  - Показывает Total pages count
- Handler: создаёт seq из 53 страниц (/, /timeline, /timeline?graph=1, /file, /finfo, /info, /diff, /blame, /annotate, /tree, /dir, /brlist, /taglist, /leaves, /stat, /zip, /tarball, /raw, /artifact, /blob, /wiki, /wiki/list, /winfo, /whistory, /wcontent, /wdiff, /ticket, /ticket/list, /tinfo, /reportlist, /report, /attach, /attachlist, /forum, /forum/list, /chat, /chat/rooms, /search, /rss, /timeline.rss, /login, /logout, /setup, /help, /sitemap, /bench, /api/v1/...)

Тест:
```
curl /sitemap
→ Sitemap - All Pages (Dynamic), Total pages: 53, группы timeline, file, wiki, ticket, forum, chat, etc.
```
