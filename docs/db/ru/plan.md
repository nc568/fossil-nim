# План развития Foccil DB

Дорожная карта построена так, чтобы каждая веха была **проверяема тестом**, а не
«примерно готова». Определение готовности: `sh tools/test.sh` зелёный + новые тесты
покрывают новую функциональность + документация обновлена на двух языках.

## v0.2 — Хранилище на диске

Цель: пережить перезапуск процесса, сохранить интерфейс исполнителя.

| # | Задача | Критерий готовности |
|---|---|---|
| 1 | `Vfs` — интерфейс (память/файл/кастом), без syscall в ядре | тесты гоняют один и тот же набор на memory-VFS и file-VFS |
| 2 | Pager: страницы 4 КиБ, кэш с LRU, грязные страницы | 100 % попаданий при повторном чтении, замерено счётчиком |
| 3 | WAL: кадры с солью и контрольной суммой, чекпойнт | тест «оборвали запись в середине кадра → БД открывается и не врёт» |
| 4 | B+tree: вставка/поиск/удаление/скан, split/merge | дифференциальный тест против in-memory индекса на 1e6 ключей |
| 5 | Freelist + авто-vacuum | размер файла не растёт при цикле вставка/удаление |
| 6 | Восстановление после сбоя (crash-recovery) | фаззер, обрывающий процесс на случайных точках |
| 7 | Шифрование страниц (XChaCha20-Poly1305, ключ вне SQL) | тест: без ключа файл нечитаем, с ключом — все данные на месте |

## v0.3 — Планировщик и производительность

1. Стоимостный выбор индекса (селективность по статистике `ANALYZE`).
2. Составные и покрывающие индексы, index-only scan.
3. Сортировка через индекс (нет materialize при `ORDER BY` по индексу).
4. Pushdown предикатов в подзапросы и CTE.
5. Профилирование: цель — точечный поиск > 500 тыс. запросов/с на 2 ядрах,
   вставка > 100 тыс. строк/с.

## v0.4 — Функциональность

1. Полнотекстовый поиск (совместимый по смыслу с FTS5: инвертированный индекс, ранжирование).
2. JSON: `json_extract`, `json_each`, `->`/`->>`.
3. Оконные функции.
4. Триггеры (осторожно: это канал эскалации привилегий — только с явным включением).
5. `ALTER TABLE` в полном объёме (перестройка таблицы с сохранением данных).

## v0.5 — cproc/QBE и встраиваемые цели

1. Совместимость с cproc: закрыть остаточные блокеры (см. `portability.md`).
2. Сборка без wasi-libc (свой bump-аллокатор) — цель < 150 КБ wasm.
3. Опциональный `-d:foccilNoAlloc` для bare-metal: арена на фиксированном буфере.

## Постоянные линии (не вехи)

* **Безопасность.** Каждая новая возможность проходит через фильтр: можно ли это
  выразить, не добавляя канал «SQL → файловая система/сеть/процесс»?
* **Потребление.** Любой рост wasm-бинарника или памяти на запрос сопровождается замером
  в PR.
* **Документация.** RU и EN обновляются в одном коммите с кодом.
* **Тесты.** Новая функциональность без теста не считается сделанной.
