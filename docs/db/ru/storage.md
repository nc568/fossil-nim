# Хранилище: VFS + pager (v0.2, срез 1)

Статус: **реализовано и протестировано** (2026-10-19). Файлы: `src/fossil/db/vfs.nim`,
`src/fossil/db/pager.nim`, `tests/db/t_storage.nim` (17 тестов).

## Зачем отдельный слой

Движок обязан оставаться чистым: тот же код исполняется в браузере и в wasm, где
`open()` не существует. Поэтому байты ходят через один узкий интерфейс:

```
движок (таблицы в памяти)  →  pager (страницы, кэш, грязные, freelist)  →  VFS (байты)
```

Хосту, который хранит страницы иначе (артефакт-стор, IndexedDB в браузере), достаточно
реализовать `Vfs` — больше ничего не меняется.

## VFS

| Бэкенд | Где доступен | Замечания |
|---|---|---|
| `openMemoryVfs()` | везде, включая JS и wasm | `string` как байтовый буфер |
| `openFileVfs(path)` | только native | на JS бросает `UNSUPPORTED` |

Страницы — это `string` намеренно: строки Nim бинарно-безопасны и не требуют
адресной арифметики, поэтому в файле нет ни `ptr`, ни `cast`, ни `addr`.

Счётчики, на которые опираются тесты: `ioReads`, `ioWrites`, `bytesMoved`.

## Pager

* **Страница 4 КиБ.** Один syscall на страницу, выравнивание по странице.
* **Страница 0 — заголовок**: магия `FOCDB\x01`, версия формата, число страниц, голова
  freelist. Чужой, обрезанный или устаревший файл отвергается с `CORRUPT` — не
  интерпретируется как валидные страницы.
* **LRU-кэш, 64 страницы по умолчанию** (256 КиБ резидентно). `readPage` возвращает
  копию: снаружи нельзя держать ссылку на страницу, которую вот-вот вытеснят.
* **Учёт грязных.** Вытесняются чистые; если грязные все — сначала flush. `flush()`
  пишет грязные страницы, затем заголовок, затем **один** `sync()`: fsync — основная
  цена по энергии, поэтому он никогда не на каждую страницу.
* **Freelist.** Освобождённые страницы переиспользуются; двойное освобождение
  отвергается с `MISUSE`, а не превращает список в цикл. `freeCount()` и
  `integrityOk()` дают тестам возможность смотреть внутрь.
* **`close()` делает flush.** Закрытие соединения не выбрасывает грязные страницы.

## Какие баги поймал этот срез

Всё это было в коде, который уже прошёл ревью:

1. **`fmReadWrite` обрезает файл.** Открытие существующей базы стирало её: Nim
   отображает `fmReadWrite` в `"w+"`. Исправлено: существующий файл открывается
   `fmReadWriteExisting`, создаётся только отсутствующий. *Именно такие баги стоят
   пользователям данных.*
2. **`failf` был шаблоном.** `%` резолвился в точке вызова, поэтому работал только
   если вызывающий модуль сам импортировал `strutils` — и только с одним аргументом.
   Переписан в процедуру с конвертером `$`: `failf(corrupt, "bad page $1", pid)`.
3. **`errors.nim` не импортировал `strutils`** — прямое следствие пункта 2.
4. **Первая страница данных выделялась с id 0** и затирала заголовок.
5. **У freelist не было защиты от двойного освобождения** — страница указывала на себя.

## Чего здесь ещё нет

WAL, B+tree, фаззинг crash-recovery, шифрование страниц, `backupTo()` — следующие
срезы v0.2. Pager намеренно простой: добавить WAL к пейджеру, про который доказано,
что он корректен, проще, чем отлаживать оба сразу.

## Как запускать

```sh
nim c -r --skipParentCfg:on --path:src tests/db/t_storage.nim
```

`--skipParentCfg:on` обязателен внутри `fossil-nim`: корневой `config.nims` линкует
`-lsqlite3 -lssl`, а этому слою они не нужны.
