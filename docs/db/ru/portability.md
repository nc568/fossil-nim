# Портируемость: C, JavaScript, wasm, cproc/QBE

## 1. Матрица целей

| Цель | Команда | Состояние |
|---|---|---|
| Нативный C (gcc/clang) | `nim c --mm:arc` | ✅ 26 + 18 тестов |
| JavaScript (V8/Node) | `nim js` | ✅ дайджест совпадает с нативным байт-в-байт |
| wasm32 | `sh tools/wasm/build.sh` | ✅ 328 КБ, работает под Node |
| cproc → QBE → musl | `sh tools/db/cproc/check.sh` | ✅ 22/22 TU, smoke-бинарник линкуется и работает |

## 2. Паритет C ↔ JS

Идея: один и тот же файл `tests/t_portable.nim` прогоняет фиксированный сценарий
(DDL, вставки, агрегаты, `GROUP BY`, `LIKE`, `CASE`, транзакции, ошибки) и печатает
**дайджест** результата: имена колонок + число строк + 32-битный FNV-1a по значениям.

```
$ nim c  -r tests/t_portable.nim | md5sum
0376a7c4c0dfd8cf602e8fcff9dddb40  -
$ nim js -r tests/t_portable.nim | md5sum
0376a7c4c0dfd8cf602e8fcff9dddb40  -
```

Требование к дайджесту: никаких `hash()` по float (представление зависит от бэкенда) и
никакой 64-битной арифметики с переполнением (в JS числа — double). Поэтому FNV-1a
32-бит с явной маской: каждое промежуточное значение < 2⁵³, значит побитово одинаково
и на x86-64, и на V8.

## 3. wasm

### 3.1 Что пришлось решить

1. **У Nim 2.2.12 нет таргета `--os:wasi`.** Рабочая комбинация: `--os:any --cpu:wasm32`.
2. **`--mm:arc` падает на freestanding:** `lib/system/arc.nim` ссылается на
   `emulatedThreadVars`, который не импортируется на этой цели. Однострочный патч
   (`elif compileOption("tlsEmulation"):`) применяется в `tools/bootstrap.sh`
   идемпотентно.
3. **`-d:noSignalHandler`** обязателен: иначе генерируется `signal(SIGFPE, …)`, которого
   в wasi-libc нет.
4. **`-d:useMalloc`** — иначе Nim тянет собственный аллокатор страниц, требующий `SysLock`.
5. **`-d:foccilNoClock`** — фиксирует часы на эпохе: запрос становится воспроизводимым, а
   ядру не нужен syscall времени.
6. **Компилятор и линкер — zig.** `zig cc -target wasm32-wasi` даёт и C-компилятор, и
   `wasm-ld`, и wasi-libc в одном 47-мегабайтном архиве. Ни emscripten, ни wasi-sdk
   не нужны. Nim не умеет `--clang.exe="zig cc"` (пробел в имени), поэтому в
   `tools/bootstrap.sh` создаются обёртки `zigcc`/`zigld`.

### 3.2 Протокол моста

Экспортируется 6 символов (каждый экспорт — поверхность атаки, поэтому мало):

```
foccil_version()            -> cstring
foccil_init()               -> void
foccil_exec(sql, params)    -> cstring (TSV-пейлоад)
foccil_exec_n(sql, params)  -> i32 (длина пейлоада)
foccil_last_ptr()           -> cstring (указатель на последний пейлоад)
malloc/free                 -> для маршаллинга строк хостом
```

Формат ответа:

```
1\nOK\n<колонки через \t>\n<число строк>\n<строка>\n<строка>…
1\nERR\n<КОД>\n<сообщение>
```

Ячейка — `тип:значение` (`i:` int, `r:` real, `s:` текст, `b:` blob, `n:` NULL).
Экранирование: `\\`, `\t`, `\n` — один раз, на выходе.

**Важно:** JS-строки в wasm не маршалятся автоматически. Хост обязан выделить память
внутри модуля (`malloc`), скопировать UTF-8 байты и передать указатель. Именно так
сделано в `tools/wasm/run.js`; это ещё и делает границу доверия явной.

### 3.3 Размер

| Шаг | Байт |
|---|---|
| наивная сборка `-O2` | 2 250 464 |
| `-Oz` + `--strip-all` + `--gc-sections` | **328 770** |

Уменьшение в 6.8 раза одним изменением флагов — то, что стоит проверять в CI, а не
обнаруживать в продакшене.

Дальнейшие цели: 150 КБ (свой bump-аллокатор вместо wasi-libc), 100 КБ
(`-d:foccilNoAlloc` с ареной на фиксированном буфере).

## 4. cproc / QBE

### 4.1 Результат

```
$ sh tools/db/cproc/check.sh
cproc gate: 22/22 translation units compiled
PASS: cproc->QBE->musl binary compiles, links and runs correctly
```

Все единицы трансляции движка проходят через **cproc → QBE → musl**, и на выходе не
просто объектный файл: настоящая программа (`tools/db/cproc/smoke.nim`) собирается,
линкуется и запускается, а её вывод сравнивается с ожидаемым. Компиляция, дающая
неработающий бинарник, гейтом не считается.

### 4.2 Почему раньше было 1/22 — три разные причины, и ни одна не в движке

| # | Симптом | TU | Настоящая причина |
|---|---|---|---|
| 1 | `qbe:-: unknown keyword extern` | 18 | **неверная версия QBE.** cproc `d1c53dd` для глобалов с внешним связыванием генерирует `extern $g`. Это синтаксис **QBE 1.3**, а `build.sh` собирал QBE 1.2. cproc не сломан — половины тулчейна были из разных лет. |
| 2 | `assignment to pointer discards qualifiers` | 7 | **кодогенерация Nim.** Nim передаёт `const`-глобал по указателю туда, где по C объект константный (`&DefaultOptions`, RTTI-таблицы, константные множества). GCC предупреждает, cproc отказывается. |
| 3 | `long double`, `__uint128_t`, `case 48 ... 57` | 3 | **стандартная библиотека Nim** рассчитана на GCC: `math.h` из musl объявляет `sqrtl`/`powl`, `pure/hashes.nim` вставляет умножение `__uint128_t`, `pure/parseutils.nim` использует GNU-диапазоны в `case`. |

Одна только починка версии QBE подняла гейт **1/22 → 12/22**. В этом вся суть K9L-35, и
это провал *документации*, а не баг компилятора: в README cproc не сказано, какой QBE ей
нужен, и на `make` ничего не падает — узнаёшь намного позже, на пятистрочном C-файле.

### 4.3 Что гейт подменяет и чего не касается

Все три оставшиеся причины — вне `src/`. Гейт их обходит, и каждый обход
**выводится во время запуска**, никогда не коммитится и не правится руками:

* **постлюдия к nimbase** (`check.sh`): `#undef NIM_CONST` / пустой `#define NIM_CONST`.
  Константные глобалы переезжают из `.rodata` в `.data`; движок их никогда не пишет,
  семантика не меняется. Одна эта строка починила 7 единиц.
* **шим `math.h`** (`shimgen.py`): минимальный заголовок с double-подмножеством. Сейчас
  используется только `fabs`; всё прочее валит гейт громко, а не тянет libm молча.
* **патч stdlib** (`shimgen.py --install`): `pure/hashes.nim` берёт свой переносимый
  128-битный fallback вместо вставки с `__uint128_t`, а в `pure/parseutils.nim` пять
  диапазонов `of '0'..'9':` развёрнуты в обычные метки — ровно то развёртывание, которое
  Nim сам делает для компиляторов без GNU-расширения. Оригиналы сохраняются как
  `*.foccil-orig`, и каждый запуск выводит патч заново из этих копий: идемпотентно и
  обратимо. `shimgen.py --check` падает громко, если stdlib перестал иметь ту форму,
  которую мы патчим, вместо тихого «ничего не сделал».

`import std/x` разрешается в обход пути поиска (и `patchFile()` к `std/`-импортам тоже
не применяется), поэтому затенять эти два файла из проекта невозможно — патч
установленного тулчейна остаётся единственным вариантом, не требующим форка stdlib
в репозитории.

### 4.4 Цена — измеренная, а не заявленная

| | cproc → QBE → musl (статически) | gcc (динамически) |
|---|---|---|
| text | 418 КБ | 376 КБ |
| data | 40 КБ | 6.7 КБ |

Сравнение не яблоки с яблоками — musl слинкован статически, glibc нет, — так что читать
это надо как «тот же порядок величины», а не как бюджет регрессии. Единственная часть,
относящаяся к шиму, — ослабление `NIM_CONST`, а это переезд `.rodata` → `.data`, не рост.

### 4.5 Что осталось открытым

* Три проблемы со stdlib оформлены одной заметкой в апстрим (K9L-36): проект на Nim
  нельзя собрать строгим компилятором C11, не пропатчив `parseutils` и `hashes`. Если в
  Nim появится `-d:strictC11`, выбирающий собственные fallback-пути, шим исчезнет.
* `build.sh` теперь отказывается работать с QBE < 1.3 вместо того, чтобы собрать
  тулчейн, валящийся через тысячу строк.
* Гейт — отдельный профиль сборки; `tools/test.sh` по-прежнему использует gcc. Зелёный
  гейт сам по себе не доказывает, что поставляемые сборки cproc-чистые — это доказывает
  smoke-бинарник, поэтому он и входит в гейт.

**Вывод:** «должен собираться cproc/QBE» теперь измерение, в конце которого работает
бинарник, а три вещи, которые этому мешали, описаны, обойдены вне движка и сами себя
проверяют.
