# WAL: надёжность без догадок (v0.2, срез 2)

Статус: **реализовано и протестировано** (2026-10-19). Файл: `src/fossil/db/wal.nim`,
тесты: `tests/db/t_wal.nim` (17 тестов).

## Контракт

> Транзакция надёжна **тогда и только тогда**, когда её кадр коммита лежит на диске
> с валидной контрольной суммой. Восстановление применяет этот префикс и ничего больше.

Прерванная транзакция не выживает частично. Она исчезает целиком — только так
пользователь может рассуждать о поведении системы.

## Раскладка

```
int8   0          магия "FOCWAL01"
int32  8          соль поколения
int32  12         число страниц на момент последнего чекпойнта
int32  16         контрольная сумма заголовка
       P, 2P, ... кадр: [pid:i32][salt:i32][crc:i32][payload: 4 КиБ]

pid >= 1            образ страницы
pid == 0x7FFFFFFF   маркер коммита; payload[0..3] = итоговое число страниц
```

Маркер коммита — **положительная** константа намеренно. Отрицательное значение
должно пережить обратное преобразование из беззнакового типа, и первая версия
молча превращала `-1` в `4294967295` — маркер не распознавался никогда.

## Что даёт каждый механизм

| Механизм | От чего защищает |
|---|---|
| CRC-32 на кадр по *pid + salt + payload* | оборванная запись не будет применена как целая |
| соль поколения в заголовке | кадры прошлого чекпойнта не будут воспроизведены вообще |
| маркер коммита | половина транзакции не станет видимой |
| один `sync()` на коммит | нет fsync на каждую страницу |

CRC **не должен** покрывать собственное поле: первая реализация считала сумму по
готовому заголовку, то есть по неинициализированным байтам, и отвергала каждый
записанный кадр.

## Групповой коммит

`appendFrame` копит образы страниц и не делает sync. `commit` пишет маркер и
выполняет ровно один sync. Двадцать страниц под одним коммитом — один fsync;
двадцать отдельных коммитов — двадцать. Тест это **измеряет**, и он же измеряет
обратный случай, чтобы цена компромисса оставалась видимой.

## Чекпойнт

`checkpoint()` сбрасывает pager, увеличивает соль и перезаписывает заголовок.
Старые кадры **не обрезаются**: они перестают совпадать по соли, и воспроизведение
останавливается на первом устаревшем кадре. Обрезка означала бы перезапись файла,
в который всё равно будут писать дальше.

## Почему один писатель

Самая известная операционная боль SQLite (см. `research-painpoints.md`) — один
писатель и стена `database is locked`. Эта схема её не прячет, а делает явной:
один журнал, один писатель, никаких переговоров о блокировках в три часа ночи.
Параллелизм — дело хоста, который может сериализовать записи осознанно.

## Чего здесь ещё нет

- фаззер crash-recovery, убивающий процесс посреди записи 1000 итераций (K9L-46);
- шифрование страниц (K9L-47);
- рост WAL за пределы одного чекпойнта на месте (упирается в формат хранения B+tree).
