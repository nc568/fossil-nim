# Чему аудит fossil-nim учит движок базы данных

Аудит от 2026-10-19 (`docs/SECURITY_AUDIT_2026-10-19_FULL_RU.md`, лежит в `main`)
бьёт по *серверной* половине проекта — REST, MCP, WebUI, sync — а не по
движку. Но прочитан он был не зря: один из его классов оказался живым в этом
коде, причём с худшими последствиями, чем на сервере.

33 находки аудита сводятся к семи формам. У каждой есть аналог на стороне
движка, и самая интересная колонка — последняя.

| Форма в аудите | Пример там | Аналог в движке хранения | Статус здесь |
|---|---|---|---|
| отсутствие аутентификации на границе | `/clone`, `/xfer`, MCP | SQL дотягивается до файла или ключа | нет `ATTACH`, нет `load_extension`, ключ — поле `DbOptions`, которого SQL не видит (K9L-83) |
| **непроверенный хеш при приёме** | `putBlob` не проверяет `hash(data) == uuid` | страница с диска не проверяется против контрольной суммы/MAC | **частично открыто** — у кадров WAL есть CRC32, у страниц основного файла нет ничего до K9L-83 |
| **поле размера используется до проверки** | заголовок блоба → OOM | `valLen` ячейки → `newString(total)` | **было сломано, теперь исправлено** — см. ниже |
| **рекурсия или цикл без бюджета** | delta-цепочки → stack overflow | цепочка overflow-страниц → бесконечный цикл; граф дерева → цикл | глубина btree ограничена 64; у overflow-цепочки теперь есть бюджет длины и проверка прогресса |
| обход путей | `fossil_rebuild` пишет куда угодно | работа с путями в VFS | движок никогда не берёт путь из SQL |
| timing-оракул | `==` на паролях | `==` на теге MAC | `constantTimeEq`, единый текст ошибки |
| неограниченная работа на запрос | нет rate-limit | запрос, который работает вечно | `maxResultRows`, `maxQueryMs`, ограничение вложенности парсера |

## Что было действительно сломано

`parseNode` в `btree.nim` доверял каждому полю страницы, которую ему дали: байту
вида, числу ячеек, таблице смещений, длине ключа, длине значения. Хватало одного
перевёрнутого байта:

```
kind=255 on page 1 -> Defect IndexDefect: index out of bounds, the container is empty
```

Это не `DbError`. `Defect` проходит сквозь любой `except DbError` в программе и
уносит с собой процесс — то есть одна испорченная страница убивает сервер,
державший сотню здоровых. SEC-12 в аудите — та же ошибка в другом костюме: поле
длины остаётся числом ровно до того момента, когда его сверили с границей.

У `readOverflow` было ещё две:

- `newString(total)`, где `total` прочитан с диска — попроси у файла гигабайт, и
  аллокатор выделит гигабайт;
- цепочка, в которой каждая страница заявляет ноль байт, не делает прогресса и
  никогда не заканчивается: ни падения, ни аллокации — просто база, которая
  навсегда перестала отвечать. Никакой сторож по памяти такого не увидит.

`freeOverflow` шёл по той же цепочке вообще без бюджета.

Все четыре исправлены в `btree.nim`; регрессия — `t_corrupt` (10 тестов). Тест
проверен единственным способом, который считается: на **старом** коде он падает
с тем самым дефектом, на новом проходит.

## Как устроен `t_corrupt`

Реальное дерево на 400 ключей (достаточно глубоко, чтобы появились внутренние
узлы) сбрасывается в байты, после чего мутируется по одному полю: вид, счётчик,
каждый байт смещения, длины ключа и значения, указатели на детей — плюс 2000
посеянных случайных мутаций по всей области страниц. Для каждого мутанта тест
открывает файл и делает всё, что делал бы читатель.

Допустимы только два исхода: правильный ответ или `DbError`. `Defect`,
`CatchableError` и любое другое исключение валят тест, потому что каждое из них
в проде — падение. Первым делом прогоняется неизменённый образ, чтобы набор,
который проходит всё подряд, не мог выдать себя за проходящий.

## Что осталось открытым, и это известно

**В основном файле нет контрольной суммы страницы.** Испорченные данные теперь
*отвергаются*, но перевёрнутый бит внутри значения — тот, что попал в полезную
нагрузку, а не в структуру, — вернётся как данные. Это ровно класс SEC-06
(«проверяй то, что принимаешь») и самый сильный аргумент за K9L-83, не
относящийся к конфиденциальности: HMAC на каждой странице превращает гниение
битов и подмену из «тихо неверно» в «отказано».

До тех пор порча основного файла обнаруживается только там, куда случайно
попал структурный байт.

## Общее правило, которое из этого следует

> Любое число, пришедшее из файла, — это число атакующего, пока оно не сверено с
> границей, которую файл не контролирует.

Применено в коде: счётчики и смещения ячеек — против `PageSize`, длины ключей —
против `MaxKeySize`, длины значений — против `MaxValueSize`, длины цепочек —
против числа страниц, глубина дерева — против 64, вложенность выражений — против
лимита парсера, строки — против `maxResultRows`.
