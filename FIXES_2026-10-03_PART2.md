# Исправления Fossil-Nim 2026-10-03 Part 2 - QBE Wrapper и --repo strip

## QBE Wrapper Fix - Критический

### Проблема

Предыдущий `qbe_nimbase.h` (минимальный 150 строк) вызывал:
- `hello_qbe` с кастомным include -> segfault 139
- `fossil-qbe-gcc version` -> segfault 139
- `fossil-qbe-gcc help` -> exit 0 но пусто (0 chars)

Тест:
```bash
nim c -d:qbeCompat --mm:refc -o:/tmp/hello_qbe2 --nimcache:... # без -I cinterop/include -> exit 0 hello
nim c -d:qbeCompat --mm:refc -o:/tmp/hello_qbe --nimcache:... -I cinterop/include -> exit 139 segfault
```
Доказано: шим ломает runtime.

### Причина

1. Минимальный шим неполный (TLS, GC, TFrame)
2. Определение `__attribute__(x)` как пустого глобально ломает glibc `extern inline` (`__gnu_inline__`), вызывая multiple definition для `atoi`, `atol`, `atoll`, `bsearch`, `atof` при `_GNU_SOURCE`:
```
system.nim.c:(.text+0x260): multiple definition of `atoi'
```
Потому что glibc с `_GNU_SOURCE` и `__OPTIMIZE__` определяет `atoi` как `extern __inline__ __attribute__((__gnu_inline__))`, а если `__attribute__` пустой, то `__gnu_inline__` теряется и функции становятся обычными extern, эмитируемыми в каждой единице трансляции.

3. Отсутствие `stdlib.h` для `abort()` -> implicit declaration

### Решение: Новый Wrapper `cinterop/include/nimbase.h`

```c
#ifdef QBE_COMPAT
#include_next "nimbase.h"  // включает оригинальный с полными определениями

#undef N_LIB_PRIVATE
#define N_LIB_PRIVATE  // убирает visibility hidden
#undef N_LIB_EXPORT
#define N_LIB_EXPORT
// ...

#undef __builtin_unreachable
#define __builtin_unreachable() abort()
#undef __builtin_expect
#define __builtin_expect(a,b) (a)
// ...

void abort(void); // без полного stdlib.h

// memmem fallback, SQLITE_TRANSIENT
#endif
```

Ключевые моменты:
- НЕ определяет `__attribute__` как пустой глобально -> сохраняет glibc inline handling
- Включает оригинальный nimbase.h через `#include_next` -> полные корректные TFrame, TSafePoint, GcFrameHeader
- Переопределяет только QBE-несовместимые части ПОСЛЕ включения
- Декларирует `abort()` без stdlib.h

## --repo strip Fix

### Проблема

`fossil sql --repo /tmp/test.fossil "SELECT ..."` включал `--repo` в query, потому что `rest` включал `--repo` и `cmdSql` делал `args.join(" ")`.

Также `branch list --repo /tmp/test.fossil` трактовал `--repo` как имя ветки.

### Решение

1. **Фильтрация глобальных флагов в main dispatcher:**
```nim
var filteredRest: seq[string] = @[]
while i<rest.len:
  if rest[i]=="--repo" and i+1<rest.len: i+=2
  elif rest[i].startsWith("--repo="): inc i
  elif rest[i]=="--backend" and i+1<rest.len: i+=2
  elif rest[i].startsWith("--backend="): inc i
  else: filteredRest.add(rest[i]); inc i
# case cmd использует filteredRest вместо rest
```

2. **Фильтрация в cmdSql:**
```nim
var filtered: seq[string] = @[]
while i < args.len:
  if args[i] == "--repo" and i+1 < args.len: i+=2
  elif args[i].startsWith("--repo="): inc i
  else: filtered.add(args[i]); inc i
let query = filtered.join(" ")
```

Применено к `main.nim` и `main_qbe.nim`.

### Результат

```bash
/tmp/fossil-full sql --repo /tmp/test.fossil "SELECT name FROM sqlite_master LIMIT 3"
# name
# ----
# blob
# delta
# config
# OK (3 rows) exit 0

/tmp/fossil-full status --repo /tmp/test.fossil
# Not in a checkout (правильно, не падает)

branch list --repo /tmp/test.fossil
# trunk (0 commits) exit 0
```
