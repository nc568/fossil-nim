# Веб-бекенды `uirelays`: найденные и исправленные дефекты

Ветка `uirelays-web-backends`. Разбор по каждой проблеме: что ломалось, где,
почему и чем подтверждено исправление.

Легенда статусов: **DONE** — исправлено и покрыто тестом; **PARTIAL** —
исправлена основная причина, осталась вторая очередь; **TODO** — не сделано.

---

## Дефекты из отчёта

### D1 — `-d:canvas` + `nim js`: тихая пустая страница — **DONE**

**Симптом.** `nim js -d:canvas examples/todo.nim` собирается без ошибок, но в
браузере — белый экран, в консоли тишина.

**Причина.** FFI-объявления канвас-драйвера были написаны так, что Nim
генерировал обращения к несуществующим JS-сущностям: тип элемента объявлялся
как обычный Nim-объект, а не как импортированный. Исключение возникало до
первой отрисовки, страница оставалась пустой, и пользователь не получал
никакой диагностики.

**Исправление.** `JsElement {.importc.} = ref object` — импортированный
opaque-тип, плюс отдельная процедура `jsRenderCanvasFrame`, которой
принадлежит весь вывод кадра. Порядок прагм в Nim важен: прагма должна стоять
**до** имени типа, иначе `Error: invalid indentation`.

**Проверка.** `nim js --mm:arc -d:canvas examples/todo.nim` → `SuccessX`,
366 КБ; `tests/web_canvas_test.nim` → 25/25.

### D2 — метрики шрифта считались как для моноширинного — **DONE**

**Симптом.** Любой шрифт, кроме моноширинного, давал неверную ширину строки:
текст обрезался или оставлял дыры.

**Причина.** `measureText` считал `ширина = число_символов × charWidth`,
то есть предполагал моноширинную сетку. Для пропорционального шрифта это
неверно в обе стороны: `iii` и `MMM` получали одинаковую ширину.

**Исправление.** Скрытый `<span>`-измеритель + кэш `__uirMeasureCache`
(сброс при превышении 16384 записей). Моноширинные семейства по-прежнему
считаются по сетке — это точнее и дешевле; для них в CSS остаётся коррекция
ячейки `letter-spacing:calc(...)`, а для пропорциональных она убрана
(`letter-spacing:normal`): коррекция 1ch имеет смысл только для сетки.

**Проверка.** `tests/web_backend_regression_test.nim` (9 проверок D2,
`-d:html` и `-d:canvas`), `tests/web_html_test.nim` → 57/57.

---

### D3 — полная перезапись `innerHTML` на каждом кадре — **PARTIAL**

**Симптом.** При каждом кадре DOM уничтожался и создавался заново: мигание,
потеря фокуса и карё, потеря выделения, «съеденные» события ввода.

**Исправлено.** Коалесцирование событий в мосте: последовательные
`MouseMove` схлопываются в одно, `mouseup` доставляется всегда (см. «Новые
дефекты» ниже).

**Осталось.** Собственно инкрементальный diff вместо полной перезаписи
`innerHTML` и доработка коалесцирования ввода. Это вторая очередь: требует
введения устойчивых идентификаторов узлов и отдельного прохода reconcile.

---

### D4 — макрос `{.uirApp.}` выбирал первый попавшийся `while` — **DONE**

**Симптом.** Если в `proc main()` был цикл инициализации перед главным
циклом, макрос превращал в кадровый цикл именно его: приложение молча
выполняло инициализацию и завершалось.

**Причина.** Выбор по первому `nnkWhileStmt` в обходе тела.

**Исправление.** Цикл считается главным, только если он **прямой оператор**
тела `{.uirApp.}` и вызывает `refresh` / `pollEvent` / `waitEvent` / `sleep`.
Если таких циклов несколько, побеждает **последний**. Если нет ни одного —
ошибка компиляции, а не тихое поведение.

**Проверка.** `tests/web_backend_regression_test.nim` компилирует два
контрольных примера: корректный (компилируется) и без цикла (ожидаемая
ошибка компиляции с упоминанием `uirApp`).

### D5 / D6 — буфер обмена и `document.title` — **DONE**

`putClipboardText` достигал системного буфера обмена и `setTitle` менял
заголовок вкладки. Проверяется в jsdom-обезьяне: `clipboardWrites > 0`,
а `tests/web_html_test.nim` → 57/57.

### D7 / D8 / D9 — окно диктовало раскладку — **DONE**

- **D7.** Минимальный размер окна задавался константами. Теперь мост читает
  `__uirMinViewport` (пол, по умолчанию 320×240) и клампит оба измерения.
- **D8.** Магические идентификаторы и жёстко прошитый отступ. Теперь
  `__uirViewportInset` — опция, по умолчанию `{x:0, y:0}`.
- **D9.** `devicePixelRatio` применялся к логическому размеру. Теперь он
  влияет только на backing store канваса (`__uirDpr`), логический размер
  остаётся в CSS-пикселях.

**Проверка.** jsdom-обезьяна проверяет контракт моста на каждом приложении,
после шторма ресайзов и после «шторма пола» (запрошен пол 500×400, сцена
сжимается до 1×1 — окно не должно сообщить размер меньше пола).

### D10 — непрозрачная заливка на весь экран стирала кадр — **DONE**

**Симптом.** `fillRect(0, 0, width, height)` непрозрачным цветом в середине
кадра удалял всё, что было нарисовано раньше, — хотя вызывающий код просил
просто прямоугольник на весь экран.

**Причина.** Оптимизация «первая заливка на весь экран = фон, можно начать
кадр заново» применялась по признаку «буфер пуст», но проверялась в момент,
когда буфер уже был очищен этой же заливкой.

**Исправление.** Проверка `htmlFrameBuffer.len == 0` выполняется **до**
добавления примитива.

**Проверка.** Две проверки в `tests/web_backend_regression_test.nim`:
наложение поверх нарисованного сохраняет оба прямоугольника; фоновая заливка
первым примитивом работает как раньше.

---

### D11 — README про BigInt / `--jsbigint64:off` — **DONE**

В README добавлен раздел «JavaScript target notes». Ключевой факт, который
был не документирован: `--jsbigint64:off` **не работает сам по себе**, он
требует `-d:nimStringHash2`, иначе сборка падает внутри `std/hashes`:

```
Error: Must use `-d:nimStringHash2` when using `--jsbigint64:off`
```

Оба варианта рабочие; смешивать их в одном бандле нельзя.

### D12 — тесты невоспроизводимы на чистом клоне — **DONE**

**Симптом.** Тесты ссылались на `/home/user/...`, `/tmp/...` и `chromium`,
поэтому на чистом клоне падали или пропускались молча.

**Исправление.**
- `tools/export_interactive_html.nim` ищет корень репозитория сам
  (переопределение — `UIRELAYS_ROOT`) и проверяет «zero canvas» политику по
  API-вызовам, а не по словам `<canvas>` / `WebAssembly` (Focim встраивает
  README, где оба слова встречаются в тексте — проверка по словам давала
  ложное срабатывание).
- `tests/monkey_browser_test.nim` и `tests/standalone_html_monkey_test.nim`
  ищут браузер через `UIRELAYS_BROWSER` или `PATH` и, не найдя его, явно
  сообщают **SKIPPED** с указанием, чем заменить.
- Добавлены два браузеронезависимых набора: `tests/server_monkey_test.nim`
  (живой нативный сервер, чистые сокеты) и `tests/jsdom_monkey_test.nim`
  (`node` + `jsdom`). Оба считают пропуски отдельным счётчиком.

## Новые дефекты, найденные в процессе

### N1 — сервер терял данные HTTP-запроса

**Симптом.** `POST /input` с 6000 событиями возвращал `ok=false, status=0`,
а `/health` показывал `totalEventsProcessed: 1668` вместо 7200. Всё, что не
влезло в первое чтение, терялось **молча**.

**Причина.** Запрос читался одним вызовом чтения фиксированного размера.

**Исправление.** Чтение до полного заголовка и тела с ограничением на размер;
неполный запрос — `400` или `413`, а не молчаливое усечение.

**Проверка.** Флуд возвращает `200` с `"queued":4096`, растёт
`droppedEvents`; `tests/server_monkey_test.nim` → 56/56.

### N2 — переполнение очереди событий роняло `mouseup`

**Симптом.** При переполненной очереди вновь пришедшее событие отбрасывалось.
Отпускание кнопки мыши терялось, и приложение «залипало» в состоянии нажатия.

**Исправление.** Очередь вытесняет **самый старый `MouseMove`**; пришедшее
событие доставляется всегда. Счётчик `droppedEvents` растёт, чтобы политика
была видна в `/health`.

**Проверка.** Три проверки в `tests/web_backend_regression_test.nim`, включая
случай «очередь забита перемещениями, приходит `mouseup`».

### N3 — битый JSON не учитывался

Малformed тело `/input` парсилось «как получится». Теперь возвращается
`200 {"added":0}` и растёт `inputParseErrors`.

### N4 — утечка файловых дескрипторов на SSE

Отключившиеся SSE-клиенты не убирались. Добавлен `reapSseClients()`; в
`/health` появились `sseClients` и `droppedEvents`. Проверяется сценарием
«24 клиента подключились, затем все собраны» (56/56).

### N5 — HTML-сборка требовала `<canvas>` в оболочке

Отчёт о контракте оболочки включал `#uir-canvas` в обязательные идентификаторы
для **обоих** бекендов. HTML-страница, которой запрещено использовать канвас,
получала предупреждение о его отсутствии и подталкивала встраивающего
добавить элемент, который драйвер использовать не будет.

**Исправление.** Список идентификаторов свой для каждого бекенда
(`__uirShellViewportId`), а обязательные элементы отделены от опциональных:
`__uirMissingElements` — только то, без чего функция мертва (viewport,
`#uir-stage`, `#uir-clipboard-input`); `__uirMissingOptional` — кнопки
тулбара, которых у минимального встраивания может не быть вовсе.

## Замечание об измерении «по обезьяньи»

jsdom не выполняет настоящий CSS-раскладку: боксы он синтезирует. Поэтому
`maxTextOverflowPx` в jsdom-отчёте (до ~910 px) — артефакт окружения, а не
дефект бекенда; доверять этой метрике стоит только в прогоне под настоящим
браузером.
